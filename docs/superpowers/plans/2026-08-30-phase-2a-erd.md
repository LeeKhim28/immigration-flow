# Phase 2A ERD Completion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finalize the approved Student Pass V1 logical data design, align the existing medical-deadline knowledge package with the selected seven-calendar-day policy, and leave a verified Phase 2B handoff.

**Architecture:** GitHub remains the canonical authoring source for official knowledge and architecture decisions. Phase 2A changes documentation and machine-readable policy only; it does not create PostgreSQL schemas or application services. A focused Ruby contract test protects the selected medical deadline and escalation behavior alongside the existing evaluator-neutral validation script.

**Tech Stack:** Markdown, Mermaid ERD, YAML, Ruby standard library with Minitest, Git, GitHub

**Spec:** `docs/superpowers/specs/2026-08-30-phase-2a-erd-design.md`

## Global Constraints

- Scope is logical data design and Student Pass V1 knowledge consistency only; PostgreSQL schemas, migrations, APIs, and application code belong to Phase 2B.
- Use a generic `case` with a one-to-one `student_pass_case_profile`.
- Treat Immigration receipt/reference time in `case_submission.accepted_at` as the formal submission time.
- Cases submitted before an official cutoff retain the previous rule assignment.
- Non-final cases submitted on or after an explicit cutoff receive a superseding assignment and automatic re-evaluation when the new policy activates.
- Completed cases are not automatically reopened.
- Supplementary submissions never change rule applicability.
- Student Pass V1 uses seven calendar days from recorded arrival for the post-arrival medical operational deadline.
- Medical lateness creates urgent human follow-up and never an automatic rejection.
- Preserve the source-language discrepancy in review records; do not misrepresent EMGS's “seven working days” wording as removed or resolved by the authorities.
- Store only synthetic applicant data and never add real identity documents or credentials.
- Rules produce preparation and triage outcomes only; no official approval or rejection outcome may be introduced.

- [ ] **Step 1: Write the failing policy-contract test**

Create `tests/rules/student-pass-v1.policy_contract_test.rb` with:

```ruby
# frozen_string_literal: true

require "minitest/autorun"
require "yaml"

ROOT = File.expand_path("../..", __dir__)

class StudentPassV1PolicyContractTest < Minitest::Test
  def setup
    requirements = YAML.safe_load(
      File.read(File.join(ROOT, "data/official-sources/extracts/student-pass-v1.requirements.yaml")),
      aliases: false
    )
    rule_set = YAML.safe_load(
      File.read(File.join(ROOT, "data/rules/student-pass-v1.yaml")),
      aliases: false
    )

    @requirement = requirements.fetch("requirements").find { |item| item.fetch("id") == "SPV1-REQ-014" }
    @due_rule = rule_set.fetch("rules").find { |item| item.fetch("id") == "SPV1-RULE-014" }
    @overdue_rule = rule_set.fetch("rules").find { |item| item.fetch("id") == "SPV1-RULE-015" }
  end

  def test_requirement_declares_seven_calendar_day_operational_policy
    handling = @requirement.fetch("machine_handling")

    assert_includes handling, "seven calendar days"
    assert_includes handling, "urgent human follow-up"
    assert_includes handling, "never automatically reject"
  end

  def test_due_and_overdue_rules_split_at_day_seven
    due_condition = condition_for(@due_rule, "medical.days_since_arrival")
    overdue_condition = condition_for(@overdue_rule, "medical.days_since_arrival")

    assert_equal({"fact" => "medical.days_since_arrival", "operator" => "lte", "value" => 7}, due_condition)
    assert_equal({"fact" => "medical.days_since_arrival", "operator" => "gte", "value" => 8}, overdue_condition)
  end

  def test_overdue_rule_escalates_without_automatic_rejection
    action = @overdue_rule.fetch("then")

    assert_equal "manual_review", action.fetch("outcome")
    assert_equal "POST_ARRIVAL_MEDICAL_OVERDUE", action.fetch("code")
    assert_equal "urgent_post_arrival_medical_follow_up", action.fetch("create_task")
    assert_includes action.fetch("message"), "seven-calendar-day"
    refute_match(/working-day interpretation/i, action.fetch("message"))
  end

  private

  def condition_for(rule, fact)
    rule.fetch("when").fetch("all").find { |condition| condition.fetch("fact") == fact }
  end
end
```
